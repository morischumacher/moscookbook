# Plan — September 2026 review

Worked top to bottom. Each phase is committed on its own so it can be reviewed
and deployed separately. `[ ]` open, `[x]` done, `[~]` needs something from the
owner (a setting or a production command only they can run).

## 1. Fix first

- [x] Weekly backup is `access: 'public'` under a guessable name → private
      path with a random secret; old public backups deleted by the next run.
- [x] Migrations cannot be applied to an empty database (`0001_invites` sorts
      before `0_init`) → rename to `0000_init`.
      [~] deploy migrations with `npm run db:deploy` from now on.
- [x] Site learning never runs: `processCapture` is never given `profiles` /
      `learnWith`, so stored profiles are never read and nothing is learned
      automatically. Wire it in, and use the same profiles in the recipe
      form's URL import.

## 2. Security

- [x] Session version on `User`: removed / demoted members, password change,
      reset and "log out everywhere" end every existing session.
- [x] Pages and the remaining routes check the database, not only the cookie
      (cook entries, photos, avatar, tickets, `GET /api/collections`).
- [x] Service worker: never cache signed-in pages; caches cleared on logout.
- [x] Image optimizer pinned to our own Blob store.
- [x] Login / forgot-password timing no longer reveals which addresses exist.
- [x] Error endpoint: cap on new rows; re-reporting does not reopen.
- [x] Fetches stop reading at the size limit instead of after it.
- [x] Missing IPv6 private ranges; archive URLs validated.

## 3. Performance and loading feedback

- [x] Service worker returns the response immediately (streaming works again),
      stays out of `/_next/`.
- [x] Recipe and home page queries in parallel; tiles select only what they show.
- [x] `loading.tsx` skeletons for every section.
- [x] One loading language for the whole app (the oyster): page skeletons,
      a navigation progress bar, a pending state on every button that waits.
- [x] Markdown rendered on the server; first tiles `priority`; Navbar profile
      shares the session lookup; admin translations kept off public pages.
      (The view counter stays a separate call: a server component cannot set
      the cookie that stops it counting twice.)
- [~] Vercel function region next to the database (`vercel.json` `regions`),
      database auto-suspend, Fluid compute — settings only the owner can check.

## 4. Architecture and code quality

- [x] One `recipeRepo` for create/update; `check:search` accepts it.
- [x] A small `route()` wrapper for auth / params / body / errors (new routes
      use it; old ones move over when they are next changed).
- [x] `RecipeForm.tsx` split into form, gallery and ingredient editor; the home
      page's searches are functions of their own.
- [x] zod for `Capture.draft` and cook-entry bodies (the archive already had it).
- [x] `failed()` logging inside `after()`; `instrumentation.ts` `onRequestError`.
- [x] Node 22 in CI and `engines`; `@types/nodemailer` to dev.
- [ ] Deferred: API error messages in German (about 210 strings; wants error
      codes translated in the client), status columns as enums (a migration
      on live data for little gain).

## 5. Admin, from the screenshots

- [x] Inbox actions: one clear primary, the rest grouped and explained.
- [x] Admin bar: Inbox first; consistent names (Inbox · Drafts · Recipes ·
      Collections · Blog | People · Reports · Devices · AI); page titles match.
- [x] Blog editor: formatting help with preview, pictures uploaded (not
      pasted URLs) and placeable inside the text, several recipes and
      collections referenced, "Address" explained, and a post linked from
      every recipe it mentions.
- [x] Collections: longer description, cover photo, simpler recipe picker,
      referencable from a post.
- [x] An example post and an example collection using everything, created from
      a button on the Blog and Collections pages and checked by the tests.

## 6. Features

- [x] Cook mode: screen stays on, one step at a time, timers from the text,
      the amounts each step needs, and a clear done / still to do.
- [x] Shopping list: add a recipe (at its scaled servings) or a whole
      collection; same ingredients combined across recipes; tick off what is
      bought; share by link; works offline.
- [x] Units: metric by default (g, kg, ml, l, EL, TL, Prise, Stück …), US
      units converted (cups by ingredient where known), amounts tidied after
      scaling (1000 g → 1 kg).
- [x] Tags and diet / time filters.
- [x] Share Target (share into the inbox from Android / desktop), keep
      favourites offline.
- [x] Ingredient sections ("For the dough"); `hreflang`.
- [x] Recipe version history with restore.
- [ ] Import from Paprika, Mealie / Tandoor and Cooklang files.

Not planned, by decision: a meal-plan calendar, and AI features for members
(the owner pays for every call).
